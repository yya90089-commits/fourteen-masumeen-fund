# Backend — طرح استقرار

این پوشه برای سرویس سمت سرور نسخه اجرایی در نظر گرفته شده است. GitHub Pages قادر به اجرای Python، نگهداری نشست امن یا ذخیره خصوصی فیش‌ها نیست.

## معماری پیشنهادی
- Frontend: HTML/CSS/JavaScript فعلی، میزبانی‌شده روی GitHub Pages یا دامنه اختصاصی.
- API: Python (FastAPI) روی یک میزبان HTTPS.
- Database: PostgreSQL برای محیط آنلاین چندکاربره؛ SQLite فقط برای توسعه محلی و آزمون.
- فایل رسید: فضای ذخیره‌سازی خصوصی با کنترل دسترسی؛ هرگز داخل پوشه عمومی وب یا Git قرار نگیرد.
- پیکربندی: متغیرهای محیطی و secret manager؛ هیچ رمز یا کلید واقعی commit نشود.

## مراحل پیاده‌سازی
1. طراحی مدل داده و migrationها: users, roles, periods, contributions, receipts, payouts, ledger_entries, notifications, messages, audit_events.
2. احراز هویت، نشست امن، کنترل دسترسی سمت سرور، CSRF و محدودیت تلاش ورود.
3. دوره‌ها، پرداخت‌ها، آپلود خصوصی رسید و گردش بررسی.
4. موتور نوبت‌بندی و قفل دریافت در صورت بدهی/رسید بررسی‌نشده.
5. دفتر کل append-only، سند اصلاحی، تأیید دوم و گزارش‌ها.
6. پیام‌ها، اعلان‌ها، داشبورد و خروجی‌ها.
7. آزمون امنیتی، پشتیبان‌گیری و استقرار.

## نکته ایمنی
تا پیش از تکمیل مراحل بالا و استقرار HTTPS، این سامانه را برای رمز واقعی، تصویر فیش، شماره حساب یا اطلاعات مالی خانواده استفاده نکنید. هیچ حساب مدیر یا رمز پیش‌فرضی در مخزن ایجاد نمی‌شود.
